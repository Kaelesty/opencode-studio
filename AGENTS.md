# OpenCode Studio — правила проекта

## Репозиторий и доставка изменений

- Это самостоятельный **Git/GitHub-проект**, не Аркадия. Здесь используйте `git`, не `arc`.
- **Все завершённые изменения нужно коммитить и пушить в GitHub.** Это постоянное разрешение владельца проекта на commit/push по итогам задач, если он явно не попросил иначе.
- В коммит включайте весь относящийся к задаче код, тесты и документацию, включая `README.md` и `AGENTS.md`. Не включайте чужие или незавершённые изменения.
- Перед коммитом проверяйте staged diff и запускайте проверки изменённого скоупа. После push проверяйте совпадение локального и удалённого коммитов.
- Если push заблокирован авторизацией или сетью, сообщите об этом явно. Локальный коммит не считается успешной публикацией.
- Не используйте force-push и не переписывайте опубликованную историю без отдельного запроса.

## Разработка

- Node.js 22+, ESM, обычный browser JavaScript/CSS. Сборщика фронтенда и базы данных нет.
- Сохраняйте существующий стиль; выбирайте небольшие локальные изменения без лишних зависимостей.
- Основные проверки: `npm test`; UI — `STUDIO_BROWSER_CHANNEL=chrome npm run test:ui` или `npm run test:ui` с установленным Playwright Chromium.
- Для сборок и тестов используйте таймаут 10 минут. Таймаут не считается успешной проверкой.
- Поиск кода выполняйте через доступный `ast-index`; перед чтением больших файлов смотрите outline.

## Конфигурация и приватность

- Проверяйте запись, миграцию и откат только на изолированных тестовых конфигурациях. Рабочую конфигурацию пользователя не изменяйте для демонстрации или проверки.
- Изменения OpenCode применяются только по явному нажатию «Сохранить». Сохраняйте проверку внешних изменений, журнал восстановления и историю снимков.
- Не обходите native permissions или системные политики OpenCode. Расширения Studio не выдавайте за нативные возможности OpenCode.
- Симлинки и защищённые источники инструкций остаются readonly.
- Никогда не коммитьте реальные конфиги, историю, ключи, токены, `.env`, логи, `node_modules` или тестовые временные каталоги. Скриншоты для README должны использовать только синтетические данные.
- Сырые ответы OpenCode API могут содержать секреты: не выводите их, даже в сообщениях об ошибках.
